# Wortlaut 0.2 – Design

Datum: 2026-10-21 · Status: freigegeben · baut auf `2026-10-21-wortlaut-design.md` auf

## Ziel

Wortlaut wird zum vollwertigen Werkzeug für Interviews und Gruppengespräche, etwa in der
qualitativen Forschung: Sprecher erkennen, Ergebnisse direkt in Analyse-Software
(MAXQDA, ATLAS.ti, NVivo) übernehmen, Transkripte dauerhaft aufbewahren und bequem
korrigieren. Die Bedienung bleibt so einfach wie in 0.1.

## Nicht-Ziele

- weitere Sprachen außer Voxtrals acht
- Modell-, CPU- oder GPU-Auswahl in der Oberfläche
- Übersetzung

## Funktionen

| Funktion | Bedienung |
| --- | --- |
| Sprecher unterscheiden | Schalter auf der Startseite (aus). Wenn an: „Anzahl: Automatisch / 2–10“. |
| Sprecher umbenennen | Klick auf das Sprecher-Etikett eines Absatzes, neuer Name gilt überall. |
| Abspielen ab Absatz | ▶ neben der Zeitmarke, schlanke Abspielleiste unten. |
| Suchen & Ersetzen | Knopf oben rechts, Leiste mit zwei Feldern, „Alle ersetzen (n Treffer)“. |
| Zusammenfassung | Knopf oben rechts, Karte über dem Text, kommt in Word und Markdown mit. |
| Verlauf | Liste links bleibt nach Neustart erhalten, Änderungen speichern automatisch, Entfernen mit Rückfrage. |
| Weitere Formate | „Weitere ▾“: Untertitel (SRT), MAXQDA, ATLAS.ti, NVivo, JSON, „Alle Formate in einen Ordner“. |

## Sprecher-Erkennung

- Bibliothek: `sherpa-onnx` (Rust-Crate 1.13.8). macOS statisch gelinkt, Windows als DLLs
  (die statischen Windows-Bibliotheken nutzen `/MT`, Rust `/MD`).
- Modelle (Teil der Einrichtung, Download wie das Sprachmodell, mit SHA256):
  - `model.onnx` aus `csukuangfj/sherpa-onnx-pyannote-segmentation-3-0`, 5 992 913 Bytes,
    SHA256 `220ad67ca923bef2fa91f2390c786097bf305bceb5e261d4af67b38e938e1079` (MIT)
  - `3dspeaker_speech_campplus_sv_zh_en_16k-common_advanced.onnx` aus
    `csukuangfj/speaker-embedding-models`, 28 281 164 Bytes,
    SHA256 `aa3cfc16963a10586a9393f5035d6d6b57e98d358b347f80c2a30bf4f00ceba2` (Apache-2.0)
- Clustering: automatisch (Schwelle 0,5) oder feste Anzahl. 8 Threads.
- Aus den Sprecherabschnitten werden **Beiträge**:
  1. nach Start sortieren; Überlappung: Start auf Ende des Vorgängers kürzen
  2. aufeinanderfolgende Abschnitte desselben Sprechers mit Lücke < 1 s verbinden
  3. Beiträge < 0,6 s verwerfen
  4. Beiträge > 30 s mit dem bestehenden Chunker in Sprechpausen teilen
  5. Sprecher in Reihenfolge des ersten Auftretens neu nummerieren
- Voxtral wandelt jeden Beitrag einzeln um. Jeder Absatz hat damit Sprecher und genaue Zeit.
- Gemessen (M5 Pro, CPU, 8 Threads): ~25–30× Echtzeit. 4/4, 2/2, 3/3 Sprecher richtig.

## Datenmodell

```
Segment    { startMs, endMs, text, speaker?: number }
Transcript { id, title, language?, sourcePath?, createdAt (Unix s), durationMs,
             speakers: string[], summary?: string, segments }
```

Alte Felder bleiben, neue haben Standardwerte (0.1-JSON bleibt lesbar).
Standardnamen „Sprecher 1 …“ bzw. „Speaker 1 …“ kommen aus der Oberflächensprache.

## Verlauf

- Ordner `<app_local_data>/transcripts/`, eine Datei `<id>.json` pro Transkript.
- `id`: `<createdAt-ms>-<4 hex>`, nur `[0-9a-f-]` erlaubt (kein Pfad-Trick möglich).
- Schreiben atomar (`.tmp` + rename). Liste nach `createdAt` absteigend.
- Die Oberfläche speichert Änderungen 800 ms nach der letzten Eingabe.

## Exporte

Überschriften („Zusammenfassung“, „Transkript“) kommen aus der Oberflächensprache.

| Format | Datei | Aufbau je Absatz |
| --- | --- | --- |
| Word | .docx | Titel, ggf. Zusammenfassung, dann `[hh:mm:ss]` (grau, optional) **Sprecher:** Text |
| Text | .txt | `[hh:mm:ss] Sprecher: Text` (Zeitmarke optional) |
| Markdown | .md | `# Titel`, ggf. `## Zusammenfassung`, `**[hh:mm:ss] Sprecher:** Text` |
| Untertitel | .srt | Hinweise ≤ 90 Zeichen, Sätze anteilig nach Zeichen auf die Absatzzeit verteilt; erster Hinweis eines Beitrags mit `Sprecher: ` |
| MAXQDA | .txt | `Sprecher: Text [hh:mm:ss]` (Zeitmarke = Ende des Absatzes) |
| ATLAS.ti | .docx | `[hh:mm:ss] Sprecher: Text` (Zeitmarke = Beginn), ohne Titel |
| NVivo | .txt | tabulatorgetrennt `hh:mm:ss.0-hh:mm:ss.0⇥Sprecher⇥Inhalt`; ohne Sprecher zwei Spalten |
| JSON | .json | das Transkript wie gespeichert |

„Alle Formate“ schreibt alle Dateien als `<Titel>.<Format>` bzw. `<Titel> (MAXQDA).txt` usw.
in einen gewählten Ordner. Ohne Sprecher-Erkennung entfällt `Sprecher: `.

## Zusammenfassung

- Voxtral im Anweisungs-Modus (`Task::Instruct`) mit einer Sekunde Stille als Audio und dem Text
  in der Anweisung. Eigene Session mit `n_ctx = 8192`.
- Text ≤ 1 200 Wörter: eine Anweisung (3–4 Sätze + Stichpunkte).
  Länger: Blöcke ≤ 1 200 Wörter an Absatzgrenzen → je 3–5 Sätze → daraus die Endfassung.
- Sprache der Zusammenfassung = Oberflächensprache. Gemessen: 2,5 s für 270 Wörter.

## Abspielen

- Asset-Protokoll von Tauri ist aktiv, Erlaubnis nur zur Laufzeit für die jeweilige
  Quelldatei (`asset_protocol_scope().allow_file`).
- Spielt die WebView das Format nicht ab oder fehlt die Datei: Hinweis statt Fehler.

## Suchen & Ersetzen

Groß-/Kleinschreibung egal, nur ganze Treffer im Text der Absätze, Anzahl live.

## Fehler

Neue Codes: `diarization_failed`, `summary_failed`, `history_failed`, `playback_unavailable`.

## Tests

- Rust: Beitrags-Bildung (Überlappung, Lücken, Kurzbeiträge, lange Beiträge, Nummerierung),
  alle Exportformate, Verlauf (speichern, auflisten, laden, löschen, ungültige ids),
  Abwärtskompatibilität 0.1-JSON, Modell-Satz-Status.
- Mit echten Modellen (per Umgebungsvariable): 3-Sprecher-Aufnahme → 3 Sprecher;
  Zusammenfassung enthält Schlüsselwörter.
- TypeScript (vitest): Suchen & Ersetzen, Text für „Kopieren“.
- Manuell in der App: Sprecher, Umbenennen, Abspielen, Suchen & Ersetzen, Zusammenfassung,
  Verlauf nach Neustart, alle Exporte.
