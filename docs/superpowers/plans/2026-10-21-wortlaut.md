# Wortlaut Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Desktop-App (Windows + macOS), die Audio/Video lokal mit Voxtral in Text umwandelt und als docx/txt/md speichert – bedienbar ohne Technikwissen.

**Architecture:** Tauri 2 mit Svelte-5-Oberfläche. Rust-Kern aus fünf Modulen (audio, chunker, engine, model_manager, export) plus `commands` als Tauri-Schicht. Die Engine nutzt `transcribe-cpp` (Metal auf macOS, Vulkan + CPU-Fallback auf Windows) und verarbeitet 20–30-s-Abschnitte nacheinander.

**Tech Stack:** Rust 1.99, Tauri 2.12, transcribe-cpp 0.4, symphonia 0.6, rubato, docx-rs 0.4, reqwest, sha2; Svelte 5, TypeScript, Vite.

**Spec:** `docs/superpowers/specs/2026-10-21-wortlaut-design.md`

## Global Constraints

- Bundle-Identifier: `io.github.zdkderpphb.wortlaut`, Produktname `Wortlaut`.
- Modell: `Voxtral-Mini-3B-2507-Q4_K_M.gguf`, URL `https://huggingface.co/handy-computer/Voxtral-Mini-3B-2507-GGUF/resolve/main/Voxtral-Mini-3B-2507-Q4_K_M.gguf`, Größe `2984721056`, SHA256 `3a6717aa8f8989108d260cbd237584289eec43cc987e10133c33643515936205`.
- Modellpfad: `<app_data_dir>/models/<Dateiname>`, Teil-Download mit Endung `.part`.
- Abtastrate für die Engine: 16 000 Hz mono f32 in [-1, 1].
- Abschnitte: min. 20 s, max. 30 s, Schnitt an der leisesten 100-ms-Stelle.
- Sprachen: `auto`, `de`, `en`, `fr`, `es`, `it`, `pt`, `nl`, `hi`.
- Oberfläche: Deutsch und Englisch nach Systemsprache, alle Texte in `src/lib/i18n.ts`.
- Keine Telemetrie, keine Netzwerkzugriffe außer dem Modell-Download.
- Lizenz MIT.

### Task 2: `transcript.rs` + `export.rs`

**Produces:** `export::to_txt(&Transcript, timestamps: bool) -> String`, `export::to_markdown(&Transcript, timestamps: bool) -> String`, `export::write_docx(&Transcript, timestamps: bool, path: &Path) -> anyhow::Result<()>`, `export::format_timestamp(ms: u64) -> String` (`hh:mm:ss`).

Tests (zuerst schreiben, fehlschlagen lassen, dann implementieren):
- `format_timestamp(3_723_000) == "01:02:03"`.
- txt ohne Zeitmarken: Absätze mit Leerzeile getrennt, getrimmt, leere Segmente ausgelassen.
- txt mit Zeitmarken: `[00:00:00] Hallo`.
- md: beginnt mit `# <title>`, Zeitmarken als `**[00:00:30]**`.
- docx: Datei existiert, ist ein ZIP, `word/document.xml` enthält Titel und Segmenttext (inkl. Umlaute, `&`-Escaping).
- [ ] Commit `feat: Export nach txt, md und docx`.

### Task 3: `chunker.rs`

**Produces:** `pub struct Chunk { pub start: usize, pub end: usize }` (Sample-Indizes), `pub fn split(pcm: &[f32]) -> Vec<Chunk>`, Konstanten `SAMPLE_RATE = 16_000`, `MIN_SECS = 20`, `MAX_SECS = 30`.

Tests:
- leer → keine Abschnitte; 5 s → ein Abschnitt `0..len`.
- 75 s Ton mit Stille bei 25 s und 52 s → Schnitte innerhalb ±100 ms dieser Stellen.
- 70 s Dauerton → kein Abschnitt länger als 30 s, keiner (außer dem letzten) kürzer als 20 s.
- Abschnitte lückenlos und decken `0..len` ab.
- Rest < 1 s wird an den vorherigen Abschnitt angehängt, solange dieser dann ≤ 31 s ist.
- [ ] Commit `feat: Abschnitte an Sprechpausen`.

### Task 4: `audio.rs`

**Produces:** `pub fn decode_to_mono_16k(path: &Path) -> Result<Vec<f32>, AudioError>`; `AudioError::{Unsupported, NoAudioTrack, Io(String)}` mit `Display` auf Deutsch-neutral (Codes, die die Oberfläche übersetzt).

- [ ] Fixtures per ffmpeg erzeugen (1 s Sinus 440 Hz, 44,1 kHz stereo) als wav, mp3, m4a (aac), ogg (opus), mp4 (aac + schwarzes Bild), flac. Einchecken.
- Tests: jede Fixture dekodiert zu 16 000 ± 400 Samples; Amplitude > 0,1; Textdatei → `Unsupported`.
- [ ] symphonia (Features: all-codecs, all-formats) + Opus über `symphonia-adapter-libopus`; Mischen auf mono; `rubato` resampelt auf 16 kHz.
- [ ] Commit `feat: Audio dekodieren und resampeln`.

### Task 5: `model_manager.rs`

**Produces:** `ModelSpec` (url, file_name, size, sha256), `pub fn status(dir: &Path, spec: &ModelSpec) -> ModelStatus` mit `ModelStatus::{Missing, Partial { bytes: u64 }, Ready}`, `pub async fn download(dir, spec, cancel: CancellationFlag, on_progress: impl FnMut(Progress)) -> Result<PathBuf, DownloadError>`, `pub fn free_space(dir) -> u64`, `Progress { downloaded: u64, total: u64, bytes_per_sec: f64 }`, `DownloadError::{Network(String), Checksum, NoSpace { needed: u64, free: u64 }, Cancelled, Io(String)}`.

Tests gegen lokalen Mini-HTTP-Server (std `TcpListener`, unterstützt `Range: bytes=N-`):
- vollständiger Download → Datei umbenannt, Status `Ready`.
- vorhandene `.part` mit halber Länge → Server erhält `Range: bytes=<halbe Länge>-`, Ergebnis korrekt.
- falsche Prüfsumme → `Checksum`, `.part` gelöscht.
- Abbruch → `Cancelled`, `.part` bleibt.
- [ ] Commit `feat: Modell-Download mit Fortsetzen und Prüfsumme`.

### Task 6: `engine.rs`

**Consumes:** `chunker::split`, `Segment`.
**Produces:** `Engine::load(path: &Path) -> Result<Engine, EngineError>`, `Engine::backend_name(&self) -> String`, `Engine::transcribe(&mut self, pcm: &[f32], language: Option<&str>, cancel: &CancelToken, on_segment: impl FnMut(&Segment, u64 /*done_ms*/)) -> Result<Vec<Segment>, EngineError>`, `EngineError::{Load(String), Cancelled, Failed(String)}`.

- Session mit `n_ctx = 2048` (30 s ≈ 375 Audio-Tokens + Text).
- Windows (`dynamic-backends`): `transcribe_cpp::init_backends_default()` einmal vor dem ersten Laden.
- Test (nur mit `WORTLAUT_MODEL=<pfad>`): deutsche Sprachprobe (per `say -v Anna` erzeugt, als Fixture eingecheckt) → Text enthält Schlüsselwörter.
- [ ] Commit `feat: Voxtral-Engine`.

### Task 7: `commands.rs` + `lib.rs`

**Befehle:** `model_info() -> ModelInfo { status, path, size, free_space }`, `download_model()`, `cancel_download()`, `transcribe(job_id, path, language, timestamps)`, `cancel_transcription(job_id)`, `export_transcript(transcript, format: "txt"|"md"|"docx", timestamps, path)`, `open_log_dir()`.
**Events:** `download-progress`, `job-progress { job_id, done_ms, total_ms, segment }`, `job-done { job_id, transcript }`, `job-error { job_id, code, detail }`.

- Engine wird lazy beim ersten Auftrag geladen und bleibt im `Mutex<Option<Engine>>`.
- Aufträge laufen über `tauri::async_runtime::spawn_blocking`, nacheinander.
