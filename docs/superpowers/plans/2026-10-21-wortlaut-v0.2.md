# Wortlaut 0.2 Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Sprecher-Erkennung, Verlauf, Exporte für Analyse-Software, Abspielen, Suchen & Ersetzen und Zusammenfassung – bei gleich einfacher Bedienung.

**Architecture:** Neues Rust-Modul `diarize` (sherpa-onnx) liefert Sprecherabschnitte, `pieces` formt daraus Beiträge, die die bestehende Engine einzeln umwandelt. `history` speichert Transkripte als JSON. `export` lernt fünf weitere Formate. Die Oberfläche zeigt Verlauf statt flüchtiger Warteliste.

**Tech Stack:** wie 0.1, dazu sherpa-onnx 1.13.8, vitest.

**Spec:** `docs/superpowers/specs/2026-10-21-wortlaut-v0.2-design.md`

## Global Constraints

- Keine Namen anderer Transkriptions-Programme in Code, Doku oder Commits.
- Modelle: Voxtral wie bisher; Segmentierung und Stimmmodell wie in der Spec (URLs, Größen, SHA256).
- 0.1-JSON muss lesbar bleiben (`#[serde(default)]` für neue Felder).
- Oberflächentexte nur in `src/lib/i18n.ts` (de/en).
- Bedienung: genau ein neuer Schalter auf der Startseite; alles Weitere in der Ergebnis-Ansicht.

---

### Task 1: Transkript-Modell und Exporte

**Files:** `src-tauri/src/transcript.rs`, `src-tauri/src/export.rs`

**Produces:**
- `Segment { start_ms, end_ms, text, speaker: Option<usize> }`
- `Transcript { id, title, language, source_path, created_at, duration_ms, speakers: Vec<String>, summary: Option<String>, segments }`
- `Transcript::speaker_name(&self, &Segment) -> Option<&str>`
- `ExportLabels { summary: String, transcript: String }` (+ `Default` = Deutsch)
- `export::render(&Transcript, Format, timestamps, &ExportLabels) -> Rendered` mit `Rendered::Text(String) | Rendered::Docx(Vec<u8>)`
- `enum Format { Docx, Txt, Md, Srt, Maxqda, Atlasti, Nvivo, Json }` mit `extension()` und `file_suffix()`

Tests: Sprecher in txt/md/docx, Zusammenfassung in md/docx, SRT (Nummerierung, Zeiten `hh:mm:ss,mmm`, Aufteilung langer Absätze), MAXQDA (Zeitmarke am Ende), ATLAS.ti (docx, Zeitmarke vorn), NVivo (Tabs, gleiche Spaltenzahl, Tabs/Zeilenumbrüche im Text ersetzt), JSON round-trip, 0.1-JSON lesbar.

### Task 2: Beiträge aus Sprecherabschnitten

**Files:** `src-tauri/src/pieces.rs`

**Produces:** `Turn { start, end, speaker }` (Samples), `Piece { start, end, speaker: Option<usize> }`, `pieces_from_turns(&[Turn], &[f32]) -> Vec<Piece>`, `pieces_without_speakers(&[f32]) -> Vec<Piece>` (Chunker).

Tests: Überlappung gekürzt, Lücke < 1 s verbunden, ≥ 1 s getrennt, < 0,6 s verworfen, > 30 s geteilt, Nummerierung nach erstem Auftreten.

### Task 3: Sprecher-Erkennung

**Files:** `src-tauri/src/diarize.rs`, `Cargo.toml` (sherpa-onnx: macOS `static`, Windows `shared`)

**Produces:** `Diarizer::new(segmentation: &Path, embedding: &Path) -> Result<Diarizer, DiarizeError>`, `Diarizer::run(&self, pcm: &[f32], speakers: Option<u32>) -> Result<Vec<Turn>, DiarizeError>`

Test (mit `WORTLAUT_DIARIZE_MODELS=<ordner>`): Fixture `dialog-de.m4a` (3 Stimmen) → 3 Sprecher.

### Task 4: Modell-Satz

**Files:** `src-tauri/src/model_manager.rs`

**Produces:** `ModelSpec::all() -> Vec<ModelSpec>` (Voxtral, Segmentierung, Stimme), `status_all(dir, &[ModelSpec]) -> ModelStatus` (Ready nur wenn alle da; Partial-Bytes summiert), `download_all(dir, specs, cancel, on_progress)` mit Gesamtfortschritt; `missing_bytes(dir, specs)`.

Tests: Status über mehrere Dateien, Gesamtfortschritt, bereits vorhandene Dateien werden übersprungen.

### Task 5: Engine (Beiträge, Zusammenfassung)

**Files:** `src-tauri/src/engine.rs`, `src-tauri/src/summary.rs`

**Produces:** `Engine::transcribe(&mut self, pcm, pieces: &[Piece], language, cancel, on_segment)`, `Engine::instruct(&mut self, prompt: &str) -> Result<String, EngineError>`; `summary::blocks(text) -> Vec<String>`, `summary::summarize(engine, &Transcript, locale) -> Result<String>`.

Tests: Blockbildung (≤ 1 200 Wörter, an Absatzgrenzen); mit echtem Modell: Zusammenfassung enthält Schlüsselwort.

### Task 6: Verlauf

**Files:** `src-tauri/src/history.rs`

**Produces:** `new_id(created_ms) -> String`, `save(dir, &Transcript)`, `list(dir) -> Vec<TranscriptMeta>`, `load(dir, id)`, `delete(dir, id)`; `TranscriptMeta { id, title, created_at, duration_ms, speaker_count, source_path }`.

Tests: Runde speichern/laden, Sortierung, ungültige id abgewiesen, kaputte Datei übersprungen, atomar (keine `.tmp` übrig).

### Task 7: Tauri-Befehle

**Files:** `src-tauri/src/commands.rs`, `src-tauri/src/lib.rs`, `src-tauri/tauri.conf.json` (assetProtocol)

**Befehle:** `transcribe(job_id, path, options { language, speakers: { enabled, count }, speakerLabel })` → speichert im Verlauf und liefert das Transkript; `history_list`, `history_load`, `history_save`, `history_delete`; `summarize(id, locale)`; `export_transcript(transcript, format, timestamps, labels, path)`; `export_all(transcript, timestamps, labels, dir) -> Vec<String>`; `allow_playback(path) -> bool`.
**Events:** `job-progress` mit neuen Stufen `diarizing`; `summary-progress { done, total }`.

### Task 8: Oberfläche

**Files:** `src/lib/*`

- Startseite: Schalter „Sprecher unterscheiden“, bei an: Anzahl-Auswahl.
- Liste links = Verlauf + laufende Aufträge.
- Ergebnis: Sprecher-Etikett (umbenennbar), ▶ je Absatz + Abspielleiste, Suchen & Ersetzen, Zusammenfassen, Weitere-Menü, Autospeichern.
- vitest für `text.ts` (Ersetzen, Kopieren).

### Task 9: Windows-Build

- sherpa-onnx als DLLs; `build.rs` sammelt `sherpa-onnx-c-api.dll` und `onnxruntime.dll` zusätzlich in `runtime/`.
- Selbsttest: Sprecher-Erkennung initialisiert (ohne Modelle: nur Laden der Bibliothek prüfen).

### Task 10: Abschluss

- In der App testen (alle Funktionen), Screenshots, README, Version 0.2.0, Tag `v0.2.0`, Release prüfen und veröffentlichen.
